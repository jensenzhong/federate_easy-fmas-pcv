# Code Review Report

> Last updated: 2026-05-25

## Scope

This review focused on the main experiment code path, data lineage, result reliability, and reproducibility. The embedded local API key in `configs/config.yaml` was intentionally preserved.

## Fixed Reliability Issues

### Multi-seed A/A' seed handling

- Files: `experiments/scenario_A_centralized.py`, `experiments/scenario_A_prime.py`, `scripts/run_multi_seed.py`
- Problem: A and A' previously did not accept a command-line seed, so multi-seed runs could silently reuse the config seed.
- Fix: Added `--seed` to A and A', and updated the multi-seed runner to pass seeds consistently.
- Impact: Multi-seed evidence now reflects actual seed variation for all supported scenarios.

### B/C statistical tests paired by row order

- File: `scripts/statistical_analysis.py`
- Problem: B vs C significance tests could pair runs by row order instead of matching `seed`.
- Fix: Statistical tests now merge B and C rows by seed before paired t-tests and Wilcoxon signed-rank tests.
- Impact: Reported p-values now correspond to matched-seed comparisons.

### Bias-corrected C metrics missing from summary

- File: `scripts/statistical_analysis.py`
- Problem: Bias-corrected C metrics were present in raw multi-seed output but absent from the summary table.
- Fix: Summary generation now includes corrected MAPE, RMSE, MAE, MPE, and R2.
- Impact: Bias correction can be evaluated from the same current summary file.

### Significance tests only printed to terminal

- File: `scripts/statistical_analysis.py`
- Problem: B vs C p-values were printed but not saved as a reproducible artifact.
- Fix: Added `results/multi_seed/significance_tests.csv`.
- Impact: Statistical claims can now be audited without relying on console history.

### LLM decision log contamination

- File: `src/federated_learning/llm_planner.py`
- Problem: `scene_C_llm_decisions.jsonl` could append across runs, making decision timelines and analysis mix old and current runs.
- Fix: The planner resets the decisions log at initialization.
- Impact: Scenario C decision logs now correspond to the current run only.

### Ablation bias correction rerun duplicated stochastic LLM calls

- File: `scripts/run_ablation.py`
- Problem: `ab-6` previously represented bias correction by rerunning Scenario C, which could create a different stochastic LLM run instead of correcting the same predictions.
- Fix: `ab-6` is now derived from `ab-5` corrected metrics when `ab-5` exists.
- Impact: Bias correction is interpreted as a post-processing comparison on the same LLM run.

### Ablation figure expected obsolete columns

- File: `scripts/generate_paper_figures.py`
- Problem: Fig.6 expected old single-run `test_mape` columns and skipped current multi-seed `test_mape_mean` data.
- Fix: Fig.6 now supports both formats and plots standard-deviation error bars for multi-seed ablation data.
- Impact: Current ablation results generate a valid paper figure.

## Current Result Interpretation

Use `results/multi_seed/statistical_summary.csv` for final B/C claims.

- B FedAvg MAPE: 51.63% +/- 5.73%
- C MAS-FL-LLM MAPE: 50.14% +/- 4.66%
- C + bias correction MAPE: 50.20% +/- 4.48%
- B vs C MAPE p-value: 0.4166, not significant
- B vs C RMSE p-value: 0.8244, not significant
- B vs C MAE p-value: 0.7489, not significant

Do not state that Scenario C comprehensively outperforms Scenario B. The current defensible wording is that C has slightly better mean MAPE/RMSE/MAE/R2 than B in this five-seed run, but the B-vs-C differences are not statistically significant at `p < 0.05`. Bias correction materially improves RMSE, MAE, MPE, and R2 for C in the current summary.

## Remaining Limitations

- The final ablation batch contains `ab-1` through `ab-4`; `ab-5`/`ab-6` LLM ablation was not rerun in that batch because external DeepSeek approval was rejected. The main C multi-seed run did complete with real LLM calls.
- Stratified evaluation currently covers A and A' only because B/C prediction CSVs are not generated by the federated scenario scripts.
- Some source comments in older scripts contain encoding artifacts. These do not affect execution, but future documentation cleanup should normalize file encoding if the scripts are edited heavily.
