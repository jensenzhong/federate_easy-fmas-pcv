# 场景 C：多智能体联邦学习造价预测方法

## 1 方法概述

场景 C 旨在构建一个由联邦学习驱动、并由智能体进行动态调控的公路工程造价预测框架。与固定聚合规则的联邦基线不同，场景 C 不仅要求各客户端在不共享原始数据的前提下协同训练一个全局预测模型，还要求系统能够在训练过程中根据各客户端的实时表现，对聚合策略、训练强度和最终绩效评价方式进行动态调整。因此，场景 C 的方法可以概括为两条相互交织的主线：第一条主线是联邦学习本身，即本地模型与联邦模型如何进行训练、交换信息、调整参数并完成性能评估；第二条主线是智能体调控机制，即系统如何基于训练历史识别当前联邦训练所处阶段，并进一步帮助全局模型进行策略切换、参数微调和绩效解释。

从研究过程上看，场景 C 按照“数据准备与联邦划分、联邦模型训练、智能体决策介入、全局模型选择与性能评价”的顺序展开。该顺序并不是出于叙述上的方便，而是由联邦学习问题本身的逻辑决定的。只有当数据被组织为多个具有异质性的客户端之后，联邦训练才具有研究意义；只有当本地模型和全局模型之间形成稳定的信息交换闭环之后，智能体的决策才具有可调控对象；也只有当训练过程中的局部更新、全局聚合和策略调整被同时记录下来，模型绩效评价才不仅是结果报告，而是对整个训练过程的结构化审查。

## 2 联邦学习主线

### 2.1 联邦场景构造与数据处理

场景 C 的数据来源于同一套清洗后的高速公路工程项目数据。研究首先在数据中保留区域标识，并依据区域样本数量对各区域进行重新组合，使样本被划分为 3 个联邦客户端。这样的处理并不是为了追求形式上的平均分组，而是为了同时满足两项要求：一是各客户端样本量尽量接近，以减轻某一客户端因数据量过大而主导全局模型的问题；二是保留不同区域之间的分布差异，使联邦训练真正面对异质数据。若仅将样本随机平均拆分，联邦场景会趋近于独立同分布，聚合策略和智能体决策的必要性会明显下降。

在联邦训练前，研究对全体样本进行两级划分。首先，在全局层面按客户端标签进行分层抽样，将数据划分为训练集、全局验证集和测试集，比例为 80%:10%:10%。全局验证集用于选择最佳通信轮次，全局测试集仅用于最终结果报告。其次，在全局训练集内部，各客户端再分别划分本地训练集和本地验证集，本地验证集比例为 20%。这一设计使本地验证集与全局验证集承担不同的功能：本地验证集为服务器判断“某一客户端本轮更新是否值得被赋予更高聚合权重”提供依据，而全局验证集则用于判断“当前全局模型是否优于历史最佳模型”。

在特征预处理方面，场景 C 采用联邦标准化而不是各客户端独立标准化。具体做法是，各客户端仅上传本地特征的和、平方和以及样本数，服务器根据这些统计量计算全局均值和标准差，再将统一的标准化参数返回给各客户端。采用这一处理方式的原因在于，联邦模型最终需要在参数空间完成加权聚合，如果不同客户端使用不同尺度的输入空间，则相同参数在不同客户端上的统计意义并不一致，聚合后的全局模型也难以保持稳定。

目标变量 `ContAmnt` 在训练前采用四次方根变换处理，即

\[
y_i^{*}=y_i^{0.25}
\]

预测结果再通过逆变换恢复到原始金额尺度。采用该变换的主要目的是缓解工程造价数据的长尾分布特征。若直接在原始金额尺度下训练，大额项目对均方误差的支配作用会过强，从而使模型更倾向于优化大型项目上的绝对偏差，而相对忽视整体样本上的相对预测误差。四次方根变换能够在压缩极端值影响的同时保留不同项目之间的量级层次，因此更适合当前造价预测任务。

### 2.2 本地模型与联邦模型的训练结构

场景 C 在客户端和服务器端采用同构的多层感知机作为基础预测器，即 `CostEstimationMLP`。模型输入维度为 10，对应 10 个输入变量，输出维度为 1，对应变换后的造价目标。网络结构为 `10-128-128-64-32-1`，隐藏层依次采用线性层、批标准化、`GELU` 激活和 `Dropout(0.1)`。选择这一结构的理由在于，公路工程造价问题中的变量关系明显具有非线性，但总体样本规模又不足以支撑过深或过宽的网络。该结构既保留了足够的非线性表达能力，又通过批标准化和轻量正则化提高了训练稳定性。

在场景 C 中，本地模型和联邦模型之间的关系不是“本地模型独立存在，联邦模型额外再训练一次”，而是“本地模型是联邦模型在各客户端上的局部展开，联邦模型则是各本地模型经服务器聚合后的共享表示”。具体而言，在每一轮通信开始时，服务器持有当前全局模型参数，并将其下发至所有客户端；各客户端以这一参数为初始化，在本地训练集上执行若干轮局部优化；局部训练完成后，客户端将更新后的参数和本地验证结果上传至服务器；服务器再根据聚合策略将这些本地更新融合成新的全局模型参数，并进入下一轮通信。这一过程不断重复，直到达到预设的通信轮数。

换言之，场景 C 中的信息交换并不是样本层面的交换，而是参数层面和状态层面的交换。留在本地的是原始工程项目数据，跨客户端流动的是模型参数和性能摘要。正是这种设计，使得系统能够在不泄露各客户端原始数据的前提下实现协同学习。

### 2.3 本地训练、参数交换与参数调整

在每轮通信中，客户端接收到全局参数后执行本地训练。设第 \(k\) 个客户端在第 \(t\) 轮开始时接收到的全局参数为 \(\mathbf{w}^{(t)}\)，则其本地训练目标可表示为

\[
\mathcal{L}_k(\mathbf{w})=
\frac{1}{n_k}\sum_{i=1}^{n_k}\left(f(\mathbf{x}_{k,i};\mathbf{w})-y_{k,i}^{*}\right)^2
+\frac{\mu}{2}\left\|\mathbf{w}-\mathbf{w}^{(t)}\right\|_2^2
\]

其中，第一项是局部预测误差，第二项为 FedProx 近端约束项。场景 C 中 \(\mu=0.01\)。引入该项的原因在于，不同区域客户端的数据分布并不一致，如果完全放任本地模型朝局部最优点快速更新，那么各客户端上传的参数方向可能出现明显分歧，最终导致聚合后的全局模型不稳定。FedProx 的作用不是削弱本地训练，而是在允许客户端学习局部特征的同时，使本地更新始终与当前全局参数保持一定耦合关系，从而抑制客户端漂移。

本地训练采用 `Adam` 优化器，基础学习率为 0.0005，本地训练轮数为 20，批量大小为 32。这里的参数选择体现了联邦训练的稳健性要求。学习率设置得低于常见集中式训练场景，是因为联邦训练中的每轮更新要同时面对客户端异质性和聚合扰动；本地训练轮数设为 20，则是在“本地学习不充分”和“本地漂移过强”之间取得折中；批量大小 32 使每个客户端在当前样本规模下既能够保持一定数量的梯度更新，又不至于因小批次波动过大而造成训练不稳定。

### 2.4 联邦模型如何进行参数聚合

当各客户端完成本地训练后，服务器端根据聚合权重对本地参数进行加权融合。若第 \(k\) 个客户端在第 \(t\) 轮上传的模型参数为 \(\mathbf{w}_k^{(t+1)}\)，其对应聚合权重为 \(\alpha_k^{(t)}\)，则新的全局参数为

\[
\mathbf{w}^{(t+1)}=\sum_{k=1}^{K}\alpha_k^{(t)}\mathbf{w}_k^{(t+1)}, \qquad \sum_{k=1}^{K}\alpha_k^{(t)}=1
\]

场景 C 并不把聚合看作一个固定不变的机械过程，而是把它视为联邦训练中最核心的调控环节。研究设置了四种候选聚合策略。`size_only` 仅按客户端样本量分配权重，反映的是统计代表性逻辑；`perf_only` 按本地验证 `MAPE` 的倒数分配权重，反映的是局部性能优先逻辑；`hybrid` 将样本量权重与性能权重进行线性组合，其中 \(\lambda=0.5\)，使两者在初始设定中具有相同影响力；`fairness_clip` 则在混合权重基础上进一步加入上下界裁剪，其中 \(\lambda=0.3\)、\(\alpha_{\min}=0.1\)、\(\alpha_{\max}=0.6\)，防止某一客户端因短期表现领先而长期垄断聚合过程。

从参数调整角度看，联邦模型与本地模型之间实际上存在两类同步调整。第一类是显式参数调整，即服务器通过聚合改变全局模型参数，再由客户端在下一轮加载更新后的全局参数继续训练；第二类是隐式训练强度调整，即由于各客户端的聚合权重和本地训练配置会变化，同一轮中不同客户端对全局模型的实际影响程度并不相同。场景 C 的关键创新之一，正是在第二类调整中引入智能体决策，而不是把聚合权重和训练超参数永久固定。

### 2.5 联邦模型绩效如何衡量

场景 C 的模型绩效评价采用多指标联合方式，而不是依赖单一误差。服务器端在全局验证集和测试集上计算 `MAPE`、`RMSE`、`MAE`、`MPE`、`NRMSE` 和 \(R^2\)。其中，`MAPE` 是主要指标，因为它能够反映不同规模项目上的相对误差控制能力；`RMSE` 和 `MAE` 分别从平方误差和绝对误差角度衡量模型稳定性；`MPE` 用于判断模型是否存在系统性高估或低估；`NRMSE` 通过范围归一化便于从相对尺度理解误差水平；\(R^2\) 则反映模型对总体变异的解释能力。

在模型选择上，场景 C 并不直接使用最后一轮训练结束时的模型，而是以全局验证集 `MAPE` 最低的轮次作为最佳通信轮次，并将该轮对应的参数保存为最佳 checkpoint。最终测试阶段，系统会恢复这一最佳 checkpoint，再在测试集上进行一次性评估。采用这一做法的原因在于，联邦训练不同轮次间常常存在性能波动，最后一轮并不必然对应最优全局状态。以验证集最优轮次为准，能够使最终结果更具有统计稳健性。

在此基础上，场景 C 还增加了一个针对系统性偏差的后处理步骤。服务器端先在全局验证集上计算 `MPE`，并据此形成比例校正因子；随后将该因子应用于测试预测结果。校正形式为

\[
\hat{y}_{corr}=\frac{\hat{y}}{1+\delta}
\]

其中 \(\delta\) 为验证集上的 `MPE`。采用比例校正而不是简单加减常数，是因为不同公路项目的造价量级差异较大，比例修正更能反映系统性高估或低估的真实程度。

## 3 智能体主线

### 3.1 智能体在场景 C 中的功能定位

场景 C 的第二条主线是智能体机制。这里的“智能体”并不是一个笼统的人工智能概念，而是指联邦训练闭环中承担不同任务的功能单元。系统中包括三个智能体：`LocalAgent`、`CentralAgent` 和 `LLMPlanner`。其中，`LocalAgent` 负责各客户端侧的局部训练与本地验证；`CentralAgent` 负责服务器侧的聚合、全局验证、最佳模型保存和偏差校正；`LLMPlanner` 负责根据训练历史做出高层决策，包括选择下一轮聚合策略、建议学习率调整和本地训练轮数调整。

之所以在场景 C 中引入智能体，是因为传统联邦平均算法虽然能够实现分布式训练，但其聚合规则和训练配置通常是静态的。在实际公路工程造价预测任务中，各区域数据质量、样本规模、分布特征和造价波动规律并不一致。如果系统始终使用固定的聚合方式和固定的训练强度，就很难根据训练阶段的变化做出针对性调整。智能体的作用，正是把原本依赖研究者人工经验进行的观察、判断和参数修改过程，转化为一个可记录、可复用和可解释的决策流程。

### 3.2 智能体如何在具体步骤中实现预定功能

场景 C 中，智能体并不是在联邦训练结束后再额外介入，而是从训练开始就嵌入到整个过程当中。具体步骤如下。

第一步，服务器初始化全局模型，并建立三个客户端智能体，每个客户端智能体分别绑定其本地训练集和本地验证集。此时，`LocalAgent` 的预定功能是执行标准化后的本地训练，并在本地验证集上计算当前轮的误差指标。也就是说，本地智能体提供的不只是更新后的参数，还提供对参数质量的局部判断。

第二步，前四轮通信采用强制探索机制，依次使用 `size_only`、`perf_only`、`hybrid` 和 `fairness_clip` 四种聚合策略。这样做的目的，是为智能体提供当前任务上的初始经验。若在一开始就让 `LLMPlanner` 自由决策，那么它缺乏足够的训练历史，只能依据一般性先验做出选择，无法真正基于当前问题的训练反馈来调控联邦系统。

第三步，从第五轮开始，`CentralAgent` 将最近 10 轮训练历史整理为结构化状态，并交由 `LLMPlanner` 分析。这一状态不仅包含全局验证 `MAPE`、`RMSE` 等指标，还包含各客户端本地验证误差、样本量和当轮聚合权重等信息。对智能体而言，这些信息构成了当前联邦训练“所处状态”的核心依据。基于这些信息，`LLMPlanner` 输出下一轮应采用的聚合策略，以及学习率缩放因子和本地训练轮数调整量。

第四步，服务器根据智能体输出更新下一轮训练配置。若 `LLMPlanner` 判断系统当前更需要保持稳定，则会倾向于推荐 `size_only` 或 `fairness_clip`；若判断当前应提高高质量客户端的影响力，则会更倾向于推荐 `perf_only` 或 `hybrid`。同时，若最近多轮全局误差改善缓慢，智能体可能建议适当提高学习率或增加本地训练轮数；若误差开始震荡，则可能建议降低学习率或减少本地训练强度。

第五步，`CentralAgent` 在每轮结束后不仅保存全局验证结果，还记录智能体决策内容及其解释。也就是说，智能体不仅执行“调整”，还生成对调整的“说明”。这使场景 C 的训练过程不再只是黑箱优化，而成为一个可以被追踪和解释的动态决策过程。

### 3.3 智能体如何帮助联邦模型调参数

在场景 C 中，智能体对联邦模型的调参作用主要体现在两个方面。

第一，智能体通过改变聚合策略，直接改变客户端更新对全局模型的影响方式。对于联邦学习而言，不同客户端的本地更新并不天然等价。某些客户端虽然样本量较大，但当轮更新质量未必最好；某些客户端虽然样本量较小，但其模型更新方向可能更接近全局最优。智能体通过在 `size_only`、`perf_only`、`hybrid` 和 `fairness_clip` 之间进行切换，使服务器能够根据训练阶段动态平衡“样本代表性”“局部性能”和“区域公平性”三类目标，而不是固定依赖单一权重逻辑。

第二，智能体通过 `lr_scale` 和 `epoch_delta` 帮助调整训练强度。场景 C 设定基础学习率为 0.0005、基础本地训练轮数为 20，并对智能体输出设置安全边界：学习率缩放系数限制在 0.5 至 2.0 之间，本地训练轮数调整量限制在 -5 至 +5 之间，最终本地训练轮数被截断在 5 至 30 范围内。之所以设置这些边界，是因为智能体在本研究中的角色是“在可控范围内优化训练”，而不是彻底重写训练过程。边界约束保证了系统即使在动态调整时也不会因一次极端决策而失去稳定性。

### 3.4 智能体如何帮助绩效评价

智能体在场景 C 中并不只用于提升训练效果，也用于帮助理解和评价训练效果。传统联邦训练常见的问题是，研究者只能在训练结束后看到误差曲线，却很难明确说明为什么某几轮性能明显改善、为什么某一策略比另一策略更适合当前任务。场景 C 通过 `LLMPlanner` 的显式决策记录，将“为什么切换策略”“为什么提高或降低训练强度”转化为训练过程中的可审查信息。

此外，智能体还通过本地验证和全局验证之间的联动帮助提升评价质量。`LocalAgent` 提供局部指标，使服务器能够理解每个客户端本轮的局部表现；`CentralAgent` 提供全局指标，使系统能够判断聚合后的整体效果；`LLMPlanner` 则把这种“局部表现—全局结果”的对应关系纳入下一轮决策。换言之，绩效评价在场景 C 中不再只是最终结果的静态测量，而是参与下一轮训练控制的动态反馈信号。

### 3.5 场景 C 中智能体机制的研究意义

从方法研究的角度看，场景 C 的核心价值并不只是“在联邦学习里增加一个大语言模型”，而是将联邦训练中的关键控制行为从隐性人工经验转化为显式智能决策。这样一来，训练过程中的聚合策略变化、学习率变化、本地训练轮数变化以及最终偏差校正，都不再是实验后难以追踪的手工调整，而成为方法本身的一部分。对于工程造价预测这样一个受数据异质性、价格波动和区域差异显著影响的问题而言，这种机制尤其重要，因为它使模型能够在保护数据隐私的前提下，不断根据训练状态进行自适应修正。

## 4 小结

场景 C 的方法可以归结为一个由联邦学习和智能体协同构成的动态优化框架。在联邦学习主线上，本地模型和联邦模型通过“全局下发、本地训练、参数上传、服务器聚合”的轮次机制完成知识交换，并通过 FedProx、动态聚合和最佳 checkpoint 选择实现参数调整与模型优化；在智能体主线上，`LocalAgent`、`CentralAgent` 和 `LLMPlanner` 分别承担局部执行、全局协调和高层决策任务，使训练过程中的聚合策略、训练强度和绩效解释能够根据训练历史进行动态调整。最终，场景 C 所得到的并不是一个静态的联邦造价预测模型，而是一套能够在异质数据环境下持续调整、持续评价并持续优化的联邦预测方法。
